# isv-dict — локальный словарь межславянского для ИИ

Локальный инструмент поверх [межславянского словаря](https://interslavic-dictionary.com)
([sonic16x/interslavic](https://github.com/sonic16x/interslavic)): те же данные (Google-таблица, ~19 100 статей,
26 языков) и та же библиотека словоизменения (`@interslavic/utils`). Сделан для того, чтобы языковая модель
могла при переводе на межславянский сверяться со словарём.

Два действия:

| | Вход | Выход |
|---|---|---|
| **lookup** | слова на **любом** языке, язык указывать не нужно | все подходящие статьи словаря: межславянское слово, часть речи, понятность, переводы на другие языки (по запросу — и все словоформы) |
| **forms** | межславянские слова (или `id:N` из lookup) | все словоформы: падежи, числа, спряжение, причастия |

Оба действия одинаково доступны через **CLI**, **HTTP** и **MCP** — параметры и JSON-ответ одни и те же.

## Установка

Нужен Node.js ≥ 20.

```bash
npm install
```

```bash
node src/cli.js update
```

`update` скачивает таблицу (~13 МБ) в `data/` и строит индекс (несколько секунд). Дальше всё работает офлайн;
повторный `update` обновляет словарь. Если `update` не запускать, данные скачаются сами при первом обращении.

## Важно: передавайте начальные формы

Для национальных языков в таблице есть только словарные формы, поэтому `собаки` или `бежал` найдены не будут —
нужно `собака`, `бежать` (им. падеж ед. числа, инфинитив). Словоформы распознаются только для самого
межславянского: `psa` → `pes` (род./вин. падеж).

## lookup — поиск

```bash
node src/cli.js lookup "собака, час" pisati --langs min
```

| Параметр | Значения | По умолчанию |
|---|---|---|
| `words` | слова или короткие фразы; `id:123` — статья по номеру | — |
| `langs` | `all` — все переводы, непроверенные с `!`; `verified` — только проверенные; `min` — `en, ru, pl` + язык, через который слово найдено; либо список кодов: `en,ru,cs` | `all` |
| `forms` | приложить все словоформы к каждой статье | нет |
| `from` | искать только в этих языках (`ru`, `uk,be`, `isv`…) | все |
| `script` | `latin` (стандартная латиница), `cyrillic`, `etymological` | `latin` |
| `limit` | сколько статей на слово отдавать целиком (остальные только перечисляются) | 5 |

Ответ на `lookup час --langs min --limit 2` (четыре совпадения из середины списка здесь опущены):

```json
{
  "queries": [
    {"query": "час", "matches": [
      {"id": 4270, "isv": "čas", "via": ["isv", "be", "uk"]},
      {"id": 1278, "isv": "časina", "via": ["ru", "sr", "mk", "bg"]},
      {"id": 13828, "isv": "vrěme", "via": ["be", "uk"], "pos": "n.", "en": "time"},
      {"id": 1732, "isv": "čaša", "via": ["isv~ form: pl.gen"], "pos": "f.", "en": "cup"}
    ]}
  ],
  "entries": [
    {"id": 4270, "isv": "čas", "pos": "m.", "posInfo": "noun, masculine, inanimate",
     "level": "2 predominantly intelligible", "intelligibility": "be+ bg- cs+ hr+ … uk+", "frequency": 9361,
     "translations": {"en": "time", "ru": "время, пора", "be": "час", "uk": "час", "pl": "czas"}},
    {"id": 1278, "isv": "časina", "pos": "f.", "posInfo": "noun, feminine", "level": "5 neologism",
     "translations": {"en": "hour", "ru": "час", "pl": "godzina", "sr": "сат, час", "mk": "час", "bg": "час"}}
  ]
}
```

Как читать:

- `queries[].matches` — всё, что нашлось по слову, лучшее сверху. `via` — через что найдено:
  - `ru`, `en`… — перевод на этот язык;
  - `!` после кода (`fr!`) — найдено через непроверенный машинный перевод;
  - `~` (`cs~`, `isv~`) — совпало только без учёта диакритики (в межславянском ещё `y`/`i`);
  - `isv` — само межславянское слово; `isv (verb without sę)` — возвратный глагол, найденный без `sę`;
  - `isv form: sg.gen` — словоформа межславянского слова и её место в парадигме;
  - `ru phrase` — слово встречается только внутри более длинного выражения.
- `entries` — полные статьи, каждая один раз: до `limit` на слово и только для лучшего вида совпадения.
  Если слово найдено как проверенный перевод или как само межславянское слово, то совпадения послабее
  (случайно совпавшая словоформа, машинный перевод, написание без диакритики) остаются только в списке
  `matches` — с частью речи и английским значением. Любую статью можно запросить отдельно: `id:1732`.
- Порядок среди равноценных совпадений: сначала само межславянское слово, потом статьи, которые подтверждает
  больше языков и которые употребительнее (поэтому `časina` «час» выше, чем `lekcija`, найденная только
  через сербский).
- Одно и то же написание в разных языках часто значит разное (`put`: английское «класть», хорватское «путь»).
  Если язык слов известен, укажите его в `from` — лишние совпадения исчезнут.
- Пояснения в скобках в запросе не учитываются, как и в самом словаре: `podhoditi (k)` ищется как `podhoditi`.
  Регистр, `ё`/`е`, пунктуация и вид дефиса тоже не важны.
- `translations`: ведущий `!` — непроверенный машинный перевод (их больше всего в `fr`, `it`, `pt`, `es`, `da`,
  `he`, `hsb`, `eo`, `de`, `sl`; точные цифры показывает `info`).
- `level` — тип слова из таблицы: 1 общепонятное, 2 преимущественно понятное, 3 регионально понятное,
  4 церковнославянизм, 5 неологизм, 9 сомнительное. `intelligibility` — понятность по языкам
  (`+` понятно, `~` частично, `-` нет). `frequency` — чем больше, тем употребительнее.
- `addition` — подсказка из словаря (род. падеж `(psa)`, основа настоящего времени `(piše)`),
  `governs` — каким падежом слово управляет.

## forms — словоформы

```bash
node src/cli.js forms pes "učiti sę" id:141
```

Принимает межславянское слово в латинице или кириллице — начальную форму, любую словоформу или `id:N`.
Параметр один: `script`. Если под написание подходят несколько статей, возвращаются все (с частью речи и
английским значением).

```json
{
  "queries": [{"query": "psa", "matches": [{"id": 2345, "isv": "pes", "via": ["isv form: sg.acc, sg.gen"]}]}],
  "entries": [{"id": 2345, "isv": "pes", "pos": "m.anim.", "posInfo": "noun, masculine, animate", "en": "dog",
    "forms": [{"lemma": "pes",
      "sg": {"nom": "pes", "acc": "psa", "gen": "psa", "loc": "psu", "dat": "psu", "ins": "psom", "voc": "pse"},
      "pl": {"nom": "psi", "acc": "psov", "gen": "psov", "loc": "psah", "dat": "psam", "ins": "psami", "voc": "psi"}}]}]
}
```

Ключи форм говорят сами за себя:

- существительные: `sg`/`pl` → `nom acc gen loc dat ins voc`;
- прилагательные: `sg.nom.{m,n,f}`, `sg.acc.m.{anim,inan}`, `sg.gen.{m/n,f}`, `pl.nom.{m.{anim,inan},f/n}`,
  `short`, `adverb`, `comparative`/`superlative` → `adj`, `adv`;
- глаголы: `infinitive`, `present`/`imperfect`/`future` → `1sg…3pl`, `perfect`/`pluperfect`/`conditional`
  (3-е лицо ед. ч. по родам), `imperative`, `lParticiple` (`m f n pl`),
  `participle.{presentActive,presentPassive,pastActive,pastPassive}`, `verbalNoun`;
- числительные и местоимения — как существительные или как прилагательные (`dva`: `m` и `f/n`).

Обозначения внутри форм: ` / ` — равноправные варианты; `mene (me)` — в скобках краткая форма;
`(n)jego` — `n-` добавляется после предлогов; `pisal(a)` — в женском роде добавляется `-a`;
`(je) pisal` — вспомогательный глагол можно опустить.

Если форм нет, статья содержит `formsNote` с причиной: несклоняемая часть речи, многословное выражение
(библиотека их не склоняет) и т. п. Одинаковые парадигмы у слов-омонимов печатаются один раз,
у остальных — `"forms": {"sameAs": <id>}`.

### Порождённые статьи

У каждого глагола есть отглагольное существительное и причастия (`zakryti` → `zakrytje`, `zakryty`,
`zakryvši`), но в словаре отдельными статьями записаны далеко не все. Библиотека даёт их только в начальной
форме, в таблице глагола. Поэтому при сборке индекса для них создаются порождённые статьи:

| вид | пример | склонение |
|---|---|---|
| отглагольное существительное | `pisanje` | как существительное ср. р. |
| действительное причастие наст. и прош. вр. | `pišuči`, `pisavši` | как прилагательное, без краткой формы |
| страдательное причастие наст. и прош. вр. | `pišemy`, `pisany` | как прилагательное, с краткой формой (`pisan`) |

Степеней сравнения и наречий у причастий нет. Поэтому находятся `zakrytja`, `pisanogo`, `pisavšego`, `zakrytoj`,
а `forms` для таких слов даёт полное склонение.

У порождённой статьи отрицательный `id`: это `id` первого глагола, от которого она построена, плюс миллион
на каждую ступень вида (0 — существительное, 1–4 — причастия в порядке таблицы выше), со знаком минус.
Например, `-20309` — существительное `zakrytje`, `-4020309` — причастие `zakryty`. Переводов у такой статьи нет,
значение берётся из глагола. В поле `derived` написано, от чего она построена:
`"verbal noun of zakryti (id 20309), zakryti (id 20310); not a dictionary entry, built from the verb"`.
Начальная форма действительного причастия совпадает с деепричастием (`pišuči` — «пиша»), об этом там тоже
написано.

Если в словаре уже есть слово той же части речи с той же леммой (существительное `pisanje`, прилагательное `mraženy`),
порождённая статья не создаётся. Сейчас порождённых статей около 14 400: 3 600 существительных
и 10 900 причастий.

## Три интерфейса

### CLI

```bash
node src/cli.js lookup "собака, дом" --langs min --pretty
```

```bash
node src/cli.js forms пес --script cyrillic
```

```bash
node src/cli.js info
```

JSON идёт в stdout, служебные сообщения — в stderr. Слова разделяются запятыми или передаются отдельными
аргументами; фразу берите в кавычки. `--max-chars N` укорачивает ответ, `--help` — справка.
Чтобы вызывать просто `isv-dict …`, выполните в папке проекта `npm link`.

### HTTP

```bash
node src/cli.js serve --port 8787
```

```bash
curl -G 'http://127.0.0.1:8787/lookup' --data-urlencode 'words=собака,дом' --data-urlencode 'langs=min'
```

```bash
curl -X POST 'http://127.0.0.1:8787/forms' -d '{"words": ["pes"], "script": "cyrillic"}'
```

`GET`/`POST` `/lookup` и `/forms` с теми же параметрами (в строке запроса или в JSON-теле), `GET /info`,
`GET /` — описание API. Сервер слушает только `127.0.0.1`.

### MCP

Сервер stdio с инструментами `isv_lookup` и `isv_forms`:

```bash
node src/mcp.js
```

- **Claude Code в этой папке** — уже настроено файлом `.mcp.json` (при первом запуске Claude Code спросит
  разрешение). Путь в нём относительный, так что Claude Code нужно запускать из корня проекта.
- **Claude Code во всех проектах** — выполнить в папке проекта:

  ```bash
  claude mcp add --scope user isv-dict -- node "$(pwd)/src/mcp.js"
  ```

- **Claude Desktop** — в `~/Library/Application Support/Claude/claude_desktop_config.json`
  (нужны полные пути; путь к `node` показывает `which node`):

  ```json
  {
    "mcpServers": {
      "isv-dict": {
        "command": "/полный/путь/к/node",
        "args": ["/полный/путь/к/local_isv_dict/src/mcp.js"]
      }
    }
  }
  ```

`words`, `langs` и `from` можно передавать списком или одной строкой через запятую.

MCP-клиенты обрезают длинные ответы инструментов, поэтому ответ ограничен 30 000 символов
(переменная `ISV_DICT_MAX_CHARS`). Если не помещается, лучшая статья каждого слова держится до последнего:
сначала длинные списки `matches` укорачиваются до десяти (в `more` — сколько не показано), потом у остальных
статей убираются формы, затем сами эти статьи, и только после этого очередь доходит до лучших. В `note`
перечислено, какие `id` дозапросить. Практичный порядок для модели: `isv_lookup` (кратко, можно
`langs: "min"` и `from`) → выбрать статьи → `isv_forms` по их `id`.

## Проверка русского текста на покрытие словарём

Чтобы заранее узнать, каких слов русского текста нет в словаре, есть два скрипта на Python с
[pymorphy3](https://github.com/no-plagiarism/pymorphy3):

```bash
python3 -m venv .venv && .venv/bin/pip install -r scripts/ru/requirements.txt
```

```bash
.venv/bin/python scripts/ru/build_lemmas.py
```

```bash
.venv/bin/python scripts/ru/check.py text.txt
```

`build_lemmas.py` собирает `data/ru_lemmas.tsv`: все русские леммы, которые словарь может перевести, в виде
`normal_form` pymorphy (строчные, ё → е), с `id` статей. Откуда берутся леммы:

| источник | что это |
|---|---|
| `dict` | однословные русские переводы статей; если pymorphy нормализует слово иначе, то и эта форма (`побеждённый` → `победить`) |
| `verbal-noun` | русские отглагольные существительные для порождённых статей: по суффиксам из перевода глагола (`закрыть` → `закрытие`), только если pymorphy знает такое существительное |
| `generated` | строки `supplement/ru_generated.tsv`, заполненные языковой моделью |

Причастиям отдельные леммы не нужны: pymorphy приводит их к инфинитиву, и `сделанный` находится через `сделать`.
Фразы («сбиваться с пути») пока не учитываются, так что слова, которые в словаре есть только внутри фраз
(«несмотря на»), считаются ненайденными. Видовые пары не достраиваются: если в словаре есть только «делать»,
слово «сделать» будет ненайденным.

`supplement/ru_generated.tsv` хранится в репозитории, `update` его не трогает. Колонки: `target`
(`derived:<порождённая статья>` или `id:<статья>`), `ru` (русские слова через запятую; пусто — русского слова нет),
`note`. Сейчас там 1 384 отглагольных существительных, которые суффиксы не нашли (`поцелуй` для `pocělovanje`;
у 129 русского слова нет), и 61 исправление русских переводов: опечатки (`шороховатый` → `шероховатый`) и
нерусские слова (`нехай` → `пусть`). Слово в таблице при этом остаётся, исправление добавляется как ещё одна лемма.
Порождённая статья находится по любому из вариантов заголовка (`derived:umŕeńje, umrěńje` найдёт статью, даже если
после `update` у неё станет другой набор вариантов). Если строка не подходит ни к одной статье, сборщик
перечисляет такие строки и завершается с кодом 1: их слов в списке нет, нужно поправить `target`.

После `update` в словаре могут появиться новые глаголы. Тогда `build_lemmas.py` запишет порождённые
существительные без русского слова в `data/ru_todo_verbal_nouns.jsonl`, и их можно так же отдать модели и дописать в
supplement. `data/ru_unknown.jsonl` — переводы, которых не знает pymorphy, для поиска опечаток; почти все они
правильные редкие слова. Сгенерированные слова, которых не знает pymorphy, сборщик перечисляет: обычно это
редкие, но правильные отглагольные существительные вроде `баррикадирование`.

`check.py` читает текст из файлов или stdin и печатает леммы, которых нет в словаре, с числом вхождений и
формами из текста (`--json` — в JSON). Слово считается найденным, если его лемма есть хотя бы в одном разборе
pymorphy. Ненайденные имена, фамилии и топонимы не выводятся, если слово написано с заглавной буквы: pymorphy
считает именами и «розу», и «льва». Сокращения («млн», «км») не выводятся, если это самый вероятный разбор.
Список помет задаёт `--skip`. Код выхода 1 — если что-то не нашлось. Оба скрипта берут папку с данными из
`ISV_DICT_DATA_DIR`, как и сам словарь.

Тесты скриптов: `.venv/bin/python -m unittest scripts/ru/test_ru.py`.

## Обновление и настройки

- `node src/cli.js update` — скачать свежую таблицу и пересобрать индекс. Запущенные HTTP- и MCP-серверы
  после этого нужно перезапустить.
- `ISV_DICT_DATA_DIR` — папка с данными (по умолчанию `data/` в проекте).
- Процесс-сервер держит словарь в памяти: примерно 170 МБ кучи.

## Ограничения

- Словоформы национальных языков не распознаются (см. выше), нечёткого поиска нет.
- Многословные статьи не склоняются; у фразовых глаголов (`iměti pravdu`) спрягается только глагол.
- Формы генерирует библиотека по правилам, а не берёт из корпуса: для редких и неправильных слов возможны
  ошибки — так же, как на сайте словаря.
- Слова, которых нет в словаре, инструмент не склоняет. Исключение — порождённые отглагольные существительные
  и причастия (см. выше).
